# Cloud executor and orchestration

Convex Workflow owns durable ordered and multi-round work. Workpool owns independent
fan-out with canonical run/component linkage. The existing OpenRouter loop preserves
provider routing, protected data behavior, progressive tools and domain callbacks.
A process that genuinely needs uninterrupted execution uses a runtime adapter.

Production does not use AI SDK WorkflowAgent or a parallel Vercel Workflow plane.
An isolated SDK comparison established basic streaming/provider-parameter parity,
not parity for branch context, deferred joins, artifact ownership, replay or the
shared client stream. Its experimental dependencies were removed.

A future executor change must demonstrate existing provider, ZDR, tool-profile,
checkpoint, streaming, fencing and effect-journal behavior, with a concrete benefit
in lifecycle complexity, cost or capability. Interoperability research does not
change which backend owns product state.
